# Диагностика сборки NIU Mobility Studio 1.2.5

## Сохранённые параметры
- `versionName = 1.2.5`
- `versionCode = 125`
- `compileSdk = 35`
- Android Gradle Plugin `8.7.3`
- Kotlin `2.0.21`
- Gradle `8.9` (совместимая версия для CI)
- JDK `17` требуется Android Gradle Plugin 8.x

## Если Android Studio показывает массовые `Unresolved reference` в AndroidX/Compose

Такие ошибки на строках `import` обычно означают, что Android Gradle Model не был успешно загружен. Это не доказывает, что каждый импорт отсутствует в исходниках.

1. Открывать нужно корневую папку проекта — ту, где лежит `settings.gradle.kts`, а не папку `app/src`.
2. Выбрать Gradle JDK 17.
3. Выполнить Gradle Sync при доступе к `google()` и `mavenCentral()`.
4. Установить Android SDK Platform 35 и Build Tools 35.0.0.
5. Сначала выполнить `:app:compileDebugKotlin`, затем `:app:assembleDebug`.
6. Если Sync завершился ошибкой, ориентироваться на первую ошибку в журнале Gradle Sync, а не на каскадные `Unresolved reference` в редакторе.

## Изменения этого исправления

- Обработка OAuth-ошибок теперь ищет описание в корневых `desc`, `message`, `error_description`, `error`, а также в `data.desc`, `data.message` и `data.error_description`.
- Код ответа API диагностируется по `status`, `code` или `retCode`.
- Отрицательное `success=false` обрабатывается без ошибочного приведения отсутствующего поля к `false`.
- Диагностика сохраняет маскирование пароля, токенов и чувствительных значений.
- Названия CI-артефактов исправлены на версию 1.2.5.

## Ограничения проверки

В среде подготовки архива отсутствуют установленный Gradle, Android SDK и доступ к сети для загрузки зависимостей. Поэтому полноценная Android-сборка и установка APK здесь не выполнялись. Этот архив нельзя считать проверенным APK; это исправленный исходный проект. Серверную проверку NIU на актуальность клиента данное изменение не обходит.
