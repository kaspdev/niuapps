# Telegram AI Bridge — NIU Mobility Studio 1.0.9

## Возможности
- `/status` — статус бота.
- `/logs` — последние 25 записей локального журнала.
- `/errors` — последние ошибки и исключения.
- `/analyze` — отправка последних 80 записей в AI backend для анализа.
- `/ai <текст>` — диалог с AI backend.
- `/fix <описание>` — запросить план/предложение исправления. Автоматическое изменение исходников не выполняется.
- Обычный текст из разрешённого Chat ID передаётся в AI backend как сообщение чата.

## Настройка
В разделе «Telegram и локальный сервер» укажите:
1. HTTPS URL собственного AI backend.
2. При необходимости Bearer token backend.
3. Токен Telegram-бота и разрешённые Chat ID.

Backend contract:
- Request: `POST application/json`
- JSON: `{"message":"...","context":{"source":"telegram","product":"NIU Mobility Studio","logs":["..."]}}`
- Response: `{"reply":"Краткий ответ пользователю"}`

Требования:
- Только HTTPS; HTTP endpoint блокируется.
- Не помещайте ключи провайдеров в приложение или репозиторий. Backend должен хранить их на сервере.
- Не включайте в ответ backend секреты или персональные данные.
- Доступ к боту ограничен allowlist Chat ID.
- В приложение передаются только последние 80 строк, с базовой маскировкой секретоподобных полей и ограничением длины.
- AI не имеет функции записи в файлы, выполнения shell-команд, установки APK или отправки команд скутеру.
- `/fix` только формирует рекомендацию. Реальное применение патча должно быть отдельной операцией с просмотром diff, backup, тестами и подтверждением в приложении.

## Примечания
AI chat требует самостоятельно развёрнутого HTTPS backend. Никакой фиктивной встроенной AI-авторизации не заявляется. Если backend не настроен, бот продолжает обслуживать `/start`, `/help`, `/status`, `/logs` и `/errors`.
