# NIU Mobility Studio

Текущая версия исходников: **1.3.2**. Резервное подключение NIU Cloud через проверяемый токен официальной сессии описано в `RELEASE_1.1.4_RU.md`. 1.1.3 — Universal NIU Android source project

**Версия приложения:** `1.1.3` · **versionCode:** `113` · **applicationId:** `com.niu.fxstudio`  
Это исходный Android-проект, а не готовый APK. Визуальная система сохраняет NIU-inspired оформление: графитовые поверхности, светлая типографика, красный акцент и компактные карточки. На телефоне используется нижняя навигация из трёх основных разделов («Главная», «Скутер», «Профиль»), на широких экранах — компактная боковая панель. Инструменты открываются из отдельного хаба, журнал ошибок доступен из верхней панели.

## Редактирование самого проекта и сборка

Приложение может импортировать архив собственных исходников, редактировать исходные файлы в приватном workspace и экспортировать изменённый проект. Это не означает возможность переписать уже установленный APK: Android изолирует установленные приложения, а самообновление бинарного кода требует отдельного подписанного пакета и подтверждения установки пользователем.

Встроенного AI backend в этой версии нет. Вход на chatgpt.com выполняется отдельно у провайдера; приложение не получает токен ChatGPT. Передача исходника/отчёта — явное действие через системное меню Android. Для встроенного AI нужен контролируемый backend с собственной OAuth-сессией.

Для GitHub откройте Code Workspace → GitHub Build Center. Один раз укажите Client ID зарегистрированного OAuth App с включённым Device Flow, войдите через официальный сайт GitHub, выберите/создайте репозиторий и ветку. Приложение поддерживает Pull/Push через Git Database API, запуск GitHub Actions, проверку статуса, загрузку APK и передачу Android Installer. Подробности — `GITHUB_INTEGRATION_RU.md`.

Облачная авторизация, QR, локальные профили устройств и ограничения binding описаны в `NIU_CLOUD_AND_VEHICLES_RU.md`. Исследование универсальной поддержки NIU и границы команд — `protocol-docs/NIU_FAMILY_SUPPORT_RU.md` и `protocol-docs/OPEN_SOURCE_PROTOCOL_RESEARCH_RU.md`.

**Подписание Release APK/AAB поддерживается условно.** В GitHub Actions Secrets добавьте `NIU_RELEASE_KEYSTORE_BASE64`, `NIU_RELEASE_KEYSTORE_PASSWORD`, `NIU_RELEASE_KEY_ALIAS`, `NIU_RELEASE_KEY_PASSWORD`. Workflow соберёт подписанные APK и AAB и опубликует artifact `NIU-Mobility-Studio-1.0.8-release`. Без всех четырёх secrets release job пропускается. Не храните ключ подписи в репозитории или APK.

## Версия 0.8.2 — исправление очереди BLE и системное сопряжение
- Все ATT-операции (READ, READ ALL, ручной WRITE и запись CCCD) проходят через общую последовательную очередь. Следующий запрос запускается только после callback предыдущего; добавлен 10-секундный тайм-аут.
- Состояние NOTIFY/INDICATE отмечается включённым только после успешного `onDescriptorWrite`, а не после принятия запроса Android.
- READ ALL исключает HID service `00001812-0000-1000-8000-00805f9b34fb`, чтение которого в журнале завершалось `BLUETOOTH_PRIVILEGED`; остальные READ-характеристики обрабатываются последовательно.
- При отключении и переподключении очередь очищается, чтобы старые операции не попадали в новую GATT-сессию.

## Подтверждённые данные проекта
В исходном журнале nRF Connect от 2026-11-01 обнаружено BLE-устройство `NIU Link F8E1`, MAC `54:88:FE:54:F8:E1`.

Сервис `8ec94e30-f315-4f60-9fb8-838830daea52` содержит:
- `8ec94e31-f315-4f60-9fb8-838830daea52` — Notify/Read, описание `Chip to App`;
- `8ec94e32-f315-4f60-9fb8-838830daea52` — Read/Write/Write No Response;
- `8ec94e33-f315-4f60-9fb8-838830daea52` — Read/Write/Write No Response, чтение в журнале возвращало GATT AUTH FAIL (0x89).

Также найден сервис `61751276-fdd6-11ed-be56-0242ac120002` с характеристикой `99ea30e2-fdda-11ed-be56-0242ac120002` (Write No Response).

Важно: названия App-to-Chip / Chip-to-App взяты из дескрипторов BLE, но формат пакетов, алгоритм аутентификации и назначение команд пока не подтверждены. Ошибка AUTH FAIL означает, что нельзя считать характеристику доступной без корректной процедуры сопряжения/авторизации.

## Чего пока нет — и почему APK не объявлен готовым
1. Нет подтверждённого протокола BLE-аутентификации для FX. Не следует отправлять случайные байты в характеристики.
2. Нет проверенного API-контракта именно для текущего китайского приложения и этой FX. Публичный старый `niu-app-api` описывает устаревшие endpoints и не доказывает совместимость с FX/актуальным CN backend.
3. Не подтверждён обход Binding Verification. Проект не подменяет владельца, не обходит серверную привязку и не меняет eSIM/TCU.
4. В доступных материалах найден только BLE-лог, но не исходный APK/дизайн-ресурсы оригинального китайского приложения. Поэтому текущая графика — оригинальная концепция, не копия экранов NIU.

Консоль регистрирует методы Bot API, HTTP-статусы, длительность запросов, входящие сообщения и callback-кнопки, сетевые ошибки DNS/CONNECT/TIMEOUT и интервалы повторного подключения. Токены и полные URL Bot API не записываются. Telegram Long Polling работает только пока процесс приложения активен; для бота требуется разрешённый Chat ID. Если уже настроен Webhook, его нужно отключить отдельно перед Long Polling.

## NIU Cloud — классическая авторизация (1.1.6)

Вход выполняется по Email/логину и паролю с выбором GLOBAL/CHINA. Ручной ввод сессионного токена удалён. Токен, выданный NIU после успешного password-login, хранится внутри приложения в Android Keystore и используется для запросов API. Ошибки HTTP 4xx/5xx разбираются с учётом серверного `desc`/`message`. Серверное требование новой версии клиента нельзя обойти подменой пароля или случайного номера версии.


### Профиль совместимости 1.1.6
Добавлен экспериментальный набор метаданных NIU Android 5.12.2 для классического входа Email/телефон + пароль. NIU не публикует актуальную схему подписи и обязательных полей, поэтому успешная авторизация не гарантируется до проверки на сервере.


## NIU Cloud login 1.1.7
Классический вход Email/логин + пароль использует документированную reverse-engineered форму `account`, `password`, `countryCode`. Приложение больше не выдаёт себя за официальный NIU app и не отправляет неподтверждённые поля версии/платформы. Совместимость с текущим сервером NIU не гарантируется: сервер может требовать закрытые параметры или подпись официального клиента.
