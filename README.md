# NIU Mobility Studio

Единый Android-проект для диагностики, настройки и управления устройствами NIU. Репозиторий содержит исходные материалы проекта, документацию, архивы версий и журнал разработки.

> **Текущий статус:** репозиторий находится в процессе восстановления и структурирования. Наличие описания функции не означает, что она проверена в исходном коде или собранном APK. Актуальные статусы и доказательства ведутся в [журнале проекта](PROJECT_PROGRESS_RU.md).

## Модель распространения

Документация проекта описывает два варианта одного приложения:

- **Full** — приложение с административной консолью и расширенными инструментами.
- **User** — пользовательский вариант с доступом к защищённым функциям только при наличии действительного разрешения.

Отдельный Admin APK не считается частью текущей подтверждённой архитектуры: административная консоль описана как встроенная в Full. До проверки исходников и сборки это архитектурное описание, а не подтверждение работающей реализации.

## Структура репозитория

- README.md — точка входа и навигация.
- PROJECT_PROGRESS_RU.md — главный журнал статусов.
- *_RU.md — документация, аудиты и спецификации.
- ZIP-архивы — исходные материалы версий; архивы сохраняются и не заменяют распакованный Android-проект.
- .github/workflows/ — ожидаемое место для CI/CD workflow после восстановления исходников и сборочной конфигурации.

Структура будет уточнена после распаковки и проверки исходного архива. Не перемещайте и не удаляйте архивы версий до проверки их содержимого и контрольных сумм.

## Ветки и версии

- main — основная интеграционная ветка; изменения, прошедшие проверку, попадают сюда.
- Ветки разработки именуются по задаче: feature/имя, fix/имя, release/версия.
- Не создавайте ветку на каждую мелкую правку.
- Ветки завершённых задач удаляются только после проверки, слияния и подтверждения, что в них нет уникальных коммитов.
- Версии публикуются через Git tags формата vMAJOR.MINOR.PATCH и GitHub Releases. Тег ставится на проверенный коммит; релиз содержит описание изменений, известные ограничения и ссылки на проверенные APK-артефакты.
- Не объявляйте ZIP или APK релизом без подтверждения версии, происхождения и результата проверки.

## Проверка и статусы

Единый источник статусов — [PROJECT_PROGRESS_RU.md](PROJECT_PROGRESS_RU.md). Используются статусы «Выполнено и проверено», «Реализовано, не проверено», «Частично», «Не выполнено», «Заблокировано» и «Документировано, код не проверен».

Каждое существенное изменение должно содержать:
1. Что изменено и где.
2. Статус проверки.
3. Доказательство: commit, PR, CI run, тест или APK artifact.
4. Что осталось сделать.

## Безопасность

- Не добавляйте keystore, пароли, токены, приватные ключи и файлы окружения с секретами в Git.
- Секреты сборки храните только в GitHub Actions Secrets.
- Для администраторских разрешений публикуйте только открытые ключи, если это предусмотрено проверенной реализацией.
- Перед сменой видимости репозитория проверьте права владельца, доступ участников, GitHub Actions, токены и внешние интеграции.
