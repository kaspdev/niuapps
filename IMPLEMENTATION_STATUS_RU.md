# NIU Mobility Studio 1.3.1 — фактический статус реализации

Этот документ различает исходный функционал, внесённые изменения и проверки, которые требуют Android toolchain/реального устройства.

## Реализовано в исходниках

- Android/Kotlin проект с модулями `app` и `niu-sdk`; административная консоль встроена в Full flavor основного приложения.
- Существующая основа NIU: BLE scan/GATT, очередь ATT, профили моделей, локальный список скутеров, диагностические экраны и ограниченный реестр ECU-команд. Поддержка каждой модели/прошивки требует испытания на реальном скутере; неподтверждённые команды не следует отправлять.
- Локальный структурированный журнал, фильтры, ротация, маскировка секретов, ручное/постоянное логирование и экспорт.
- Внешние облачные сервисы логирования Webhook/WebDAV/S3 не используются; дополнительные облачные интеграции отложены. Наличие NIU Cloud-клиента в исходной основе сохранено.
- `full` и `user` product flavors. В `user` исходники защищённых инструментов остаются в проекте, но доступ к защищённым маршрутам требует действительного подписанного разрешения. Локальное логирование остаётся доступным.
- Admin генерирует ECDSA P-256 ключ в Android Keystore; закрытый ключ не экспортируется. Открытый ключ закрепляется в User APK через `NIU_ADMIN_PUBLIC_KEY`.
- Admin выдаёт ECDSA-подписанное разрешение, привязанное к Installation ID, с перечнем возможностей и сроком до 365 дней. User проверяет подпись, привязку, срок и идентификатор grant перед доступом.
- Admin защищает выпуск и отзыв PIN-кодом; хранится PBKDF2-HMAC-SHA256 verifier с солью.
- Admin подписывает офлайн-список отзыва. User проверяет подпись, хранит объединённый список и блокирует отозванный grant после импорта.
- В User есть экран импорта разрешения и списка отзыва; доступ к управлению разрешением есть также из хаба защищённых инструментов.
- GitHub Build Center умеет публиковать Workspace, запускать workflow, проверять статус и скачивать выбранный артефакт. Full, User и Admin APK публикуются как отдельные артефакты; в приложении добавлен выбор типа APK.
- Release-сборка включает R8 и shrinkResources. Release-подпись требует собственного keystore и секретов CI.

## Ограничения, которые нельзя скрывать

- Отзыв офлайн-разрешения не может быть мгновенным без связи. Список отзыва должен быть доставлен и импортирован на User устройстве; автоматического BLE-обмена разрешениями пока нет.
- Grant привязан к Installation ID приложения, а не к серийному номеру скутера/ECU. Перепривязка к VIN/SN потребует отдельного протокола регистрации устройства.
- PIN Admin — локальный барьер, не защита от владельца root-устройства, модификации APK или компрометации ОС.
- Android-приложение не компилирует APK на телефоне само по себе. Создание APK выполняется Gradle на GitHub Actions runner через Build Center после настройки OAuth App, репозитория и GitHub variable `NIU_ADMIN_PUBLIC_KEY`.
- Если `NIU_ADMIN_PUBLIC_KEY` не задан в GitHub Actions Variables, User APK будет собран без доверенного ключа и не сможет принять разрешения. Сначала установите Admin, создайте ключ, затем задайте переменную и пересоберите User.
- Экспорт установленного APK и получение свежего APK из Build Center — разные операции. Для распространения User APK выбирайте `USER APK` в Build Center.
- Компиляция Kotlin/Android, unit tests, APK и работа BLE/ECU на реальном скутере не подтверждены в текущей среде: здесь нет Gradle и Android SDK. Проверены структура проекта, XML/YAML и синтаксический разбор Kotlin без Android classpath; это не заменяет полноценную Gradle-сборку.

## Сборка

`./BUILD_ALL.sh` требует JDK 17, Gradle 8.9+ и Android SDK 35. Он запускает JVM-тесты и собирает Full, User и Admin debug APK. Для пользовательской сборки задайте `NIU_ADMIN_PUBLIC_KEY` (Base64 X.509 SubjectPublicKeyInfo). GitHub workflow `.github/workflows/android-build.yml` выполняет те же действия на runner и публикует три отдельных APK-артефакта.
