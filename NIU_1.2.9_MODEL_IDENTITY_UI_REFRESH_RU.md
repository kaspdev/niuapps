# NIU Mobility Studio 1.2.9 — Model Identity & UI Refresh

## Что изменено
- Cloud vehicle parser теперь сохраняет server-side поля `type`, `productType`, `vehicleTypeId`, `brand`, `specialEdition`, `frameNo` (VIN), `engineNo` и `isDoubleBattery`.
- Классификация модели выполняется по серверным полям в приоритетном порядке; имя, заданное владельцем, не используется как доказательство модели.
- Ранее вручную выбранный профиль FX не перезаписывается общим/конфликтующим `type=GOVA` при очередном импорте. Явный FX-маркер в `productType`, `vehicleTypeId` или `specialEdition` имеет приоритет.
- В журнал добавляется безопасная сводка полей идентификации, без публикации полного SN/VIN.
- Cloud ↔ BLE bridge сравнивает семейство по серверным метаданным, а не по пользовательскому имени скутера.
- Верхняя кнопка настроек открывает контекстное меню быстрых переходов; длинные описания в каталоге инструментов сокращены, убраны дублирующие info-кнопки.
- Версия сохранена: `versionName=1.2.9`, `versionCode=129`.

## Ограничения
- `motoinfo/list` возвращает серверные поля, но их конкретные значения/кодировка зависят от региона и модели. Неизвестный `vehicleTypeId` не декодируется догадками.
- VIN (`frameNo`) сохраняется для точной идентификации; он сам по себе не гарантирует известную таблицу соответствия модели.
- FX profile retention — защита пользовательского выбора, а не утверждение, что сервер подтвердил FX. Для окончательного серверного подтверждения требуется явный FX-маркер в метаданных NIU.
- Android build не запускался в среде без Gradle Wrapper/установленного Gradle.
